# Post-Pipeline

The post-pipeline performs a final round of LLM-based deduplication across the FAQ questions generated by the main pipeline, then produces the final deliverable CSV per crop.

**Location**: `post_pipeline/`
**Entry point**: `run_post_pipeline.py` (see [Entry Points](entry_points.md))

---

## File Structure

```
post_pipeline/
├── post_processing_dedup.py   # LLM deduplication logic
└── get_final_output.py        # Utility: collect final CSVs into a single folder
```

---

## `post_processing_dedup.py`

### Overview

Deduplicates FAQ questions **within each category** using a two-phase LLM verification strategy, then aggregates frequency counts of merged questions.

**Model used**: Gemma-4-26B (Google, via HuggingFace)

### Algorithm

```
For each crop:
  Load unique_questions_freq_qa.csv
  Group rows by Generated_Category
  
  For each category:
    pool = all rows in this category
    
    While pool is not empty:
      reference = first row in pool
      pool = remaining rows
      
      Phase 1 (LLM candidate search):
        Ask LLM: "Which of these questions are semantically equivalent to <reference>?"
        → candidates list
      
      Phase 2 (LLM verification):
        Ask LLM: "Confirm which of these candidates truly match <reference>."
        → verified matches
      
      Aggregate: reference.raw_frequency += sum(match.raw_frequency for match in verified)
      Remove verified matches from pool
      Keep reference
    
    Output: deduplicated rows for this category
```

Returns:
- `result_df`: deduplicated DataFrame with aggregated frequencies
- `log_df`: phase-by-phase matching log (`phase_data_faq.csv`)

### Log Format (`phase_data_faq.csv`)

Each row in the log records one reference question's deduplication round:

| Column | Description |
|---|---|
| `reference_id` | Row index of the reference question |
| `reference_text` | The reference question text |
| `phase1_candidates` | Questions flagged as similar in Phase 1 |
| `phase2_verified` | Questions confirmed as duplicates in Phase 2 |
| `phase1_false_positives` | Questions in Phase 1 that Phase 2 rejected |
| `aggregated_frequency` | Final frequency after merging duplicates |
| `category` | `Generated_Category` value |

---

## Output

For each crop the post-pipeline produces:

| File | Location | Description |
|---|---|---|
| `phase_data_faq.csv` | `outputs/repair/<state>/<crop>/` | LLM deduplication audit log |
| `<state>_<crop>.csv` | `outputs/repair/<state>/<crop>/` | Final deduplicated FAQ (no `(unclassified)` rows) |

The final CSV keeps the same columns as `unique_questions_freq_qa.csv` but:
- Removes rows where `Generated_Category == "(unclassified)"`.
- Aggregates `raw_frequency` across merged duplicates.

---

## `get_final_output.py`

A standalone utility that collects the per-crop final CSVs into one place:

```bash
python post_pipeline/get_final_output.py \
  --input outputs/repair/karnataka_norm \
  --output app-data/final/karnataka
```

For each crop subfolder that contains `unique_questions_freq_qa.csv`, copies it to `<output>/<crop>_faq.csv`.

---

## `meta.json`

After the post-pipeline completes for a crop, `run_post_pipeline.py` writes (or updates) `meta.json` in the crop output folder. The frontend reads this to show download/audit status badges.

```json
{
  "downloaded": false,
  "audited": false,
  "post_pipeline_done": true,
  "final_csv": "karnataka_norm/cotton/karnataka_norm_cotton.csv"
}
```
